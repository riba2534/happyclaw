# 群消息候选预处理

团队模式已经具备意图识别和自动工作项：`team-gate.ts` 根据群的准入表产生推断候选，
路由 Agent 根据启用规则判断意图，`work_route` 在 `observe` 下只记录 `would_accept`，
在 `auto` 下创建工作项。这里增加的是调用模型之前的可选防抖和本地初筛，首版沿用团队
模式的飞书普通群支持范围。工作项是 Agent 执行的工作，和人工待办清单、飞书原生任务
或自动化定时提醒不是同一种对象。

## 开启方式

使用现有的、只允许工作区所有者调用的团队设置 API：

```text
PUT /api/workspaces/:workspaceJid/team-mounts/:channelJid
```

保留已有 `settings.enabled`、`admission`、`acceptMode` 和 `rules`，增加以下字段。
为避免误接单，建议先在 `acceptMode: "observe"` 下检查规则；满意后再切为 `auto`。

```json
{
  "candidateIntake": {
    "enabled": true,
    "quietMs": 6000,
    "maxWaitMs": 30000,
    "maxMessages": 10,
    "keywords": [
      "待办",
      "跟进",
      "截止",
      "审批",
      "发一下",
      "整理",
      "下班前",
      "明天",
      "周一",
      "周二",
      "周三",
      "周四",
      "周五"
    ],
    "prioritySenderIds": ["ou_project_lead"]
  }
}
```

以上是 `settings` 内的片段，不是完整请求体。省略 `candidateIntake` 时保持原有行为。
设置页面保存其他选项时会保留已通过 API 配置的值；首版不新增设置控件。

边界：静默时间 1–30 秒，最长等待 1–120 秒且不小于静默时间，最多 1–50 条。
关键词最多 100 个、每个最多 80 字符；高优成员最多 100 个、每个 ID 最多 256 字符。
关键词是大小写不敏感的字面字符串，不执行用户提供的正则。默认关键词见
`DEFAULT_TEAM_CANDIDATE_INTAKE`。

## 消息怎么处理

例如同群连续到达三条消息：

1. 「刚才那个客户诉求」；
2. 两秒后「谁去跟进一下」；
3. 再两秒后「今天下班前搞定」。

第三条之后静默六秒，整个兼容批次才进入初筛。到达十条或最长等待三十秒会提前结束窗口；
单批文本达到 32000 字符也不再继续等待。明确 @ 请求、工作项跟进、不同账号、群或话题
构成边界，不和前面的推断候选混为一批。噪声不参与关键词匹配；纯表情、标点、确认语
（如「收到」「好的」「谢谢」「1」）组成的批次直接跳过。图片、文件和结构化引用没有可用
关键词时仍交模型处理，避免因为占位文本而漏掉任务。

命中关键词或高优发送者的有效正文后，原始消息作为一个有序批次进入现有路由 Agent，
每条仍保留自己的发送者、消息 ID 和授权事实。工作项执行会话也能读到宿主选择的完整
拆句上下文。高优成员必须配置精确的 IM 用户 ID；展示名、正文自称主管都无效。
放行只跳过关键词筛选，不会跨越群的 audience、准入表、`acceptMode`、模型规则或工作项
修改授权。模型仍可忽略候选；多个句子是否构成同一任务仍由现有路由逻辑决定。

消息和服务端接收时间先持久化到 SQLite，计时器只负责唤醒处理；冷启动、暖 Runner 与
排队提升都检查同一预处理规则。服务重启不会丢掉窗口中的消息，已经超时的批次不再等待。
被过滤的输入保留在历史里，由既有游标/队列完成机制消费，不再反复触发模型。

## 验证与限制

```bash
npm test -- --run tests/team-candidate-intake.test.ts tests/team-candidate-runtime.test.ts tests/team-gate.test.ts tests/team-host-wiring.test.ts tests/work-item-service.test.ts tests/routes-work-items.test.ts
```

测试使用假时钟和临时 SQLite 数据库，不请求模型或真实群聊。覆盖静默窗口重置、条数和
最长等待上限、纯闲聊零模型准入、高优成员 ID、账号/话题隔离、重启恢复、排队入口和工作项
拆句上下文。关键词会有误报和漏报，应按实际群聊调整；没有真实标注样本时不宣称固定的
过滤率、识别准确率或 token 节省比例。
