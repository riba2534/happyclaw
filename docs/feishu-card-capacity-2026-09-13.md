# 飞书单卡容量验收（2026-09-13）

前一版原生路径固定每 12,000 UTF-8 字节续卡，并有单组件 30,000 字符截断与过期的定稿 15,000 字符门槛。这些属于项目策略，不是 CardKit 的统一硬限制。

官方流式 content 字段上限为 100,000 字符。创建与全量更新卡片 JSON 的字符串字段另有更大的限制；文档中的 30KB 消息体及 200860 排查提示不能直接当作实体引用式 CardKit 的正文上限。复杂 Markdown 会在飞书服务端膨胀，未公开完整计算规则。

## 真实 API 探针

全部调用由 Mac mini 使用现有应用身份执行，未复制凭据或创建部署备份。

多正文槽协议也已通过真实 SDK 验证：在同一未发送实体动态增加两个空 Markdown 槽，分别流式写入 99,000、99,000、2,000 个 ASCII 字符，再删除额外槽并关闭流式，所有接口返回成功。

## 实施策略

- 整卡按实际运行态与完成态 JSON 检查容量，正文优先，计入详情、页脚、组件数及未来用量更新。
- 单个流式 Markdown 组件最多使用 99,000 Unicode 字符；超出时优先在同一张卡片追加正文组件，而不是立即发新卡片。
- 默认原始 JSON 容量采用 300,000 bytes；对服务端明确拒绝的隐藏渲染容量限制，自动收紧失败页预算并重试。网络确认不确定仍停止重发，防止重复消息。
- 全文装得下时保持单卡；段落或围栏边界只有在填充率足够高时才优先，避免产生只有开头几行的小卡片。
- 已确认的历史页边界保持稳定；仅 canonical 正文回撤时重新协调，始终保留全部原文。
