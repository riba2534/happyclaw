# 飞书普通回复容量（2026-09-13）

普通回复的原生富文本（post）及纯文字（text）使用独立的消息容量预算，不沿用 CardKit 的 300KB 实体预算。原先的 2,400 字节限制只用于同一 post 内的 Markdown 节点，不会产生额外消息；真正缺少的是整条消息的容量检查。

## 官方说明与真实接口

[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)和[回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply)说明文字为 150KB、富文本为 30KB，并提示样式可能扩大消息体。[内容结构](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)没有为单个 post.md 节点声明独立字符上限。

Mac mini 使用现有应用身份执行的真实接口结果如下。大容量探针只使用本次自行创建的测试消息，完成后撤回探针正文或恢复简短摘要。

| 操作                | 内容                          | 内层 content JSON 字节 | 外层 msg_type/content JSON 字节 | 结果        |
| ------------------- | ----------------------------- | ---------------------: | ------------------------------: | ----------- |
| create post         | 40,000 ASCII                  |                 40,448 |                          40,620 | 成功        |
| create post         | 100,000 ASCII                 |                101,073 |                         101,445 | 成功        |
| create / reply post | 150,000 ASCII                 |                151,598 |                         152,138 | 成功        |
| create / reply post | 160,000 ASCII                 |                161,698 |                         162,270 | 230025 超限 |
| create text         | 151,000 ASCII                 |                151,011 |                         151,047 | 成功        |
| create text         | 160,000 ASCII                 |                160,011 |                         160,047 | 230025 超限 |
| update text         | 49,000 中文                   |                147,011 |                         147,047 | 成功        |
| reply / update text | 70,000 引号与反斜杠           |                140,011 |                         280,047 | 成功        |
| reply post          | 重复加粗与链接                |                 64,948 |                          66,552 | 成功        |
| update post         | 单 Markdown 节点 27,000 ASCII |                 27,048 |                          27,092 | 成功        |

当前租户实际 create/reply 接口可以发送远超文档 30KB 的 post；外层二次 JSON 转义也不是实测总量判定依据。工程默认采用 **150,000 字节的内层 content JSON**，保留少量余量；它是基于当前接口的策略，不是所有内容与未来版本的统一承诺。服务端明确返回 **230025** 时缩小失败页。230001 也可能表示结构或内容错误，不按容量重试。

## 发送与恢复

- 全文能放进一条消息时保持一条，仅超过整消息预算时按接近容量的边界分页。
- 富文本页面按真实格式化后的 JSON 计量；同一消息内部继续使用小 Markdown 节点，保留代码围栏和表格。纯文字不添加 Markdown 或改写原文。
- 原生普通回复每个物理页面对应独立 Outbox 记录；超限只重规划失败页，已确认页不重复发送。所有替代子页确认后，将超限父记录标记为已被替代，避免回合误报失败；恢复沿同一记录树执行。
- 无法确认是否送达的请求保持停止重发；超时按单页控制，即使晚到确认，也不继续启动后页。
- 图片说明、无 Outbox 普通发送、卡片格式降级后的富文本均使用容量检查；多页中途失败保留已发送进度。
- 修复超长代码围栏标记超过节点预算时，分段循环无法前进的问题。
