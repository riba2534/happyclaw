# 远端 MCP 配置与排查

本指南说明如何通过 Web 界面添加带 Header 的远端 MCP，并确认它进入指定智能体的
能力配置。示例地址 `https://mcp.example.com/mcp` 和 `<YOUR_TOKEN>` 都是占位，
使用时请替换为服务文档提供的地址和凭据。

## 1. 选择传输与作用域

先确认服务端要求的传输，不能只看 URL 是否以 `https://` 开头：

| 服务端提供的传输 | Web 中的类型 | URL 填写方式 |
| --- | --- | --- |
| Streamable HTTP | `HTTP` | 填服务给出的 MCP 端点，例如 `https://mcp.example.com/mcp` |
| SSE | `SSE` | 填服务给出的 SSE 端点，例如 `https://mcp.example.com/sse` |

不要把普通网页、模型 Provider 的 API Endpoint 或 STDIO 命令填作远端 MCP URL。
路径以服务端说明为准；不要自行把 `/mcp` 改为 `/sse` 来切换传输。

作用域决定配置由谁维护，以及哪些用户的智能体可以使用：

| 归属范围 | 维护者 | 可用范围 |
| --- | --- | --- |
| 我的 MCP | 当前用户 | 当前用户的智能体，另受各智能体 MCP 选择限制 |
| 系统 MCP → 仅管理员 | 管理员 | 管理员的智能体；普通成员能看到系统条目，但不能使用 |
| 系统 MCP → 共享给成员 | 管理员 | 成员的智能体也可使用，另受各智能体 MCP 选择限制 |

个人凭据优先放在“我的 MCP”。“共享给成员”会把完整配置（包括 URL、Headers 等）
交给成员的智能体运行。只有确认这些凭据和对应服务权限允许成员使用时才开启共享；
界面不显示密钥不代表运行时没有使用它。权限详情见 [ACL 权限矩阵](ACL-MATRIX.md)。

## 2. 添加 URL 与 Headers

1. 登录后打开 **能力库 → MCP**（`/capabilities/mcp`），点击 **添加**。
2. 管理员可选择 **归属范围**；个人接入选择 **我的 MCP**。普通成员创建的是自己的 MCP。
3. 填一个容易识别且不与现有配置同名的 **服务器 ID**，例如 `remote-tools`。
   ID 只能含字母、数字、短横线和下划线，必须以字母或数字开头；`happyclaw` 是保留 ID。
4. 根据服务说明选择 **HTTP** 或 **SSE**，填写完整 **URL**。
5. 服务要求鉴权时点击 **添加 Header**，把 Header 名与值分别填写。Bearer 示例：

   | Header 名 | Header 值 |
   | --- | --- |
   | `Authorization` | `Bearer <YOUR_TOKEN>` |

   将 `<YOUR_TOKEN>` 替换为自己的真实 Token，保留 `Bearer` 后的一个空格。
   若服务要求不同 Header（例如 `X-API-Key`），按其文档填写；不要自动添加 `Bearer`。
   每个 Header 只填一行，同名行不会合并。无鉴权要求的服务可不填 Header。
6. 点击 **添加**，在列表确认该条目已启用。保存配置不等于已经连接服务或调用工具成功。

Header 值框是密码输入框。保存后密钥不会回填：重新打开详情时看不到值，并不表示
已经丢失。只修改 URL 或描述时保留当前 Headers 即可；更换凭据时在详情 **编辑** 中
点击 **替换全部**，完整重填所有需要保留的 Headers 后保存。此操作替换整组，
遗漏的 Header 不会保留；**清空全部** 会移除整组 Headers。

## 3. 让指定智能体使用并检查最终能力

添加到能力库后，还要核对智能体的能力策略：

1. 打开 **智能体**（`/agent-profiles`），选择要使用它的智能体。
2. 在 **能力配置 → HappyClaw MCP** 中选择：
   - **使用全部 HappyClaw MCP**：继承当前用户可用且启用的配置。
   - **只允许所选 HappyClaw MCP**：勾选 `remote-tools` 的正确来源（“我的”或“系统”）。
   - **关闭 HappyClaw MCP**：不加载能力库中的这些附加 MCP。
3. 保存配置。管理员配置内置主 HappyClaw 时，在 **设置 → 主 HappyClaw** 的
   **模型与系统附加能力 → HappyClaw MCP** 中配置，并点击 **保存模型与能力**。
4. 在智能体页的 **最终生效能力** 中选择实际要运行的工作区，刷新预览。
   检查 MCP 列表中的 ID、来源和同名覆盖提示。带删除线的不可用系统条目不能用于运行。
   没选工作区时，预览无法完整反映该工作区的项目级 MCP。
5. 在该智能体所属工作区的会话里，明确请求一次服务提供的、无副作用的工具调用。
   查看工具轨迹和返回结果，确认调用的是预期 MCP；模型文字声称“已连接”不能替代
   实际工具调用结果。

**最终生效能力** 是配置预览，不进行远端连通性或鉴权测试。发送消息后可刷新
**最近真实运行** 快照核对运行配置；快照同样不能替代某个工具的成功返回。

同名的系统与个人 MCP 默认以个人配置优先。宿主机、工作区原生 MCP 与能力库是
叠加来源：**关闭 HappyClaw MCP** 不会关闭工作区原生 MCP 或从宿主机配置继承的 MCP。
遇到来源不符时先看预览，避免仅凭服务器 ID 判断使用了哪组凭据。

## 4. 按失败阶段排查

| 现象 | 优先检查 |
| --- | --- |
| 添加时提示 ID 已存在或格式错误 | 在同一作用域使用唯一、合法的 ID；不要使用保留 ID |
| 成员能看到系统 MCP，但无法选择/预览显示不可用 | 请管理员核对“成员访问”；仅管理员条目不会进入成员智能体运行配置 |
| 能力库有条目，智能体预览里没有 | 条目是否启用、智能体是否关闭或未选中它，以及所选工作区/来源是否正确 |
| 预览里显示同名覆盖 | 个人与系统、宿主机或工作区是否有同名 MCP；核对最终来源或改用不同 ID |
| 运行提示所选 MCP 不可用 | 精确选择的配置可能已删除、禁用或不再对该用户开放；先修复智能体选择 |
| HTTP 401/403 | Header 名、完整值、空格、Token 有效期和服务端权限；换 Key 时是否漏填其他 Header |
| HTTP 404、协议错误或返回网页 | URL 路径和 HTTP/SSE 类型是否与服务说明一致；该地址是否只是网站或普通 API |
| DNS、TLS、连接超时 | 从智能体实际运行的 Host 或 Container 环境核对网络、证书和代理；浏览器能访问不代表 Runner 能访问 |
| 工具可见但调用失败 | 查看该次工具返回的参数、权限、额度或服务端错误；发现成功不等于每个工具都可调用 |

远端 URL 中的 `localhost`/`127.0.0.1` 指智能体实际运行环境自身。在 Container 模式下，
它通常不是 HappyClaw 主服务所在的宿主机；本机服务需要使用该运行环境可访问的地址。
不要通过关闭证书校验或把 Token 拼到 URL 查询串来“修复”连接问题。

向项目反馈时提供 HappyClaw 版本或 commit、Host/Container 模式、传输类型、失败阶段
及脱敏后的错误。删除 Header 值、URL 中的凭据/私人参数和工具输入中的敏感内容；
无需上传整个运行数据目录。接口导航见 [API 文档](API.md#skillsmcp-和-plugins)。

## 5. 凭据与运行数据

- 不把真实 Token 写入 Git 跟踪的 `.mcp.json`、项目文档、示例、截图、Issue 或聊天日志；
  需要展示时只用占位。不要让智能体打印完整 Headers 或密钥。
- Web 中保存的 MCP 凭据会持久化到实例的私有运行数据；“不回显”不等于“不落盘”。
  当前 MCP 配置与秘密分开保存在 `data/mcp-servers/` 下，秘密文件以受限文件权限保存，
  不是加密凭据库。保护运行目录及服务账户权限，不要把 `data/` 加入 Git 或公开打包上传。
- 共享系统 MCP 前核对 Key 的服务端权限、费用和所有允许使用它的成员。远端调用会把
  对应工具输入发送到服务端；按服务要求使用最小权限凭据。
- 如果凭据曾进入公开材料，应先在服务端吊销或轮换，再在 MCP 详情中替换完整 Headers；
  删除帖子或本地文件不能使旧 Key 失效。
